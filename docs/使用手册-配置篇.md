## 1. 快速开始

### 1.1 环境要求

| 依赖 | 版本 | 必需性 | 用途 |
|---|---|---|---|
| Go | 1.26+ | 必需 | 构建/运行后端 |
| Node + npm | Node 24 | 必需（看界面时） | 构建/运行前端；本仓库只用 npm，不要用 pnpm |
| protoc 等 | — | 可选 | 仅重新生成 proto 代码时需要（`make proto`） |
| PostgreSQL | — | 可选 | 持久化场次/事件/审计/设置/账本/弹幕/幂等键 |
| Redis | — | 可选 | WS ticket、HMAC nonce、幂等键的跨实例共享 |
| ffmpeg | — | 可选 ⚠️ 未验证 | 音频解码/重采样；未安装时相关能力标记不可用 |

### 1.2 构建并启动后端（Windows PowerShell）

```powershell
cd f:\myproject\teamwork\digital-human
go build -o bin\dh.exe ./cmd/dh
.\bin\dh.exe -conf configs\config.yaml
```

默认监听 `127.0.0.1:8795`，安全模式 `local`（仅本机回环可访问）。

启动日志里这两行是**预期**的降级提示（无 PG/Redis 时）：

```
WARN postgres dsn empty; running degraded (no persistence)
WARN redis addr empty; 幂等/ticket 使用进程内实现
```

### 1.3 验证后端活着

```powershell
curl.exe -i http://127.0.0.1:8795/healthz
```

缺 PG/Redis 时返回（默认 `health.require_dependencies=false`，2026-11-04 起）：

```json
HTTP/1.1 200 OK
{"capabilities":{"engine_dev":false,"ffmpeg":false,"omnivoice":false,"postgres":false,"redis":false,"vidu":false},
 "data":{"postgres":false,"redis":false},"degraded":true,"status":"degraded","missing":["postgres","redis"],
 "limits":{"max_sessions":1},"ok":false,"phase":"idle","version":"0.1.0-m0"}
```

**三态语义（2026-11-04 起）**：依赖就绪 → 200 + `status=ok`；缺依赖默认仍返回 **200**（进程可服务即存活，无 PG/Redis 的降级运行是支持模式），以 `status=degraded` + `missing` 名单显式标注——降级不是启动失败；`health.require_dependencies=true` 恢复旧行为（缺依赖返回 **503**）。PG/Redis 接齐后无需重启会自动转 ok（探测有 5s 缓存）。

### 1.4 启动前端

```powershell
cd f:\myproject\teamwork\digital-human\web
npm install
npm run dev      # http://localhost:9000
```

开发服务器把 `/api`、`/healthz`、`/ws` 代理到 `127.0.0.1:8795`（见 `web/quasar.config.js` devServer 配置）。生产构建：

```powershell
npm run build    # 产物在 web\dist\spa
```

生产构建为纯静态文件，需要自行用任意静态服务器托管，并把 `/api`、`/ws` 反代到后端（dev 代理只在 `npm run dev` 时存在）。

### 1.5 「没有 Vidu Key / OmniVoice / PG 时是什么状态」

照实说（✅ 本机实测）：

- 页面能正常打开、所有面板可用（设置/弹幕/口播/歌曲等纯后台功能可用）。
- 点「开始直播」→ `POST /api/v1/live/start` 返回：

```json
HTTP/1.1 503 Service Unavailable
{"code":503,"reason":"engine_unavailable",
 "message":"engine_not_configured: missing_credentials: DH_VIDU_KEY,DH_OMNIVOICE_ADDR"}
```

- RTC 区域显示「RTC 未配置（后端未下发凭据）」。
- **不能开播、不能说话、没有画面**。只有配置齐 Vidu Key + OmniVoice 地址（或显式 `DH_ENGINE_MODE=dev` 假引擎）后才有直播链路。

## 2. 依赖与凭据逐项说明

> 铁律：**敏感值只走环境变量，不写进 yaml**（`internal/conf/config.go`：`ViduKey`/`APISecret`/`CollectorSecret` 等字段标注 `yaml:"-"`，即使写进 yaml 也不会被读取）。

### 2.1 配置加载顺序

默认值（代码内置）→ `configs/config.yaml` → 环境变量覆盖（仅密钥类与少数字段）。配置加载后做合法性校验，非法组合直接拒绝启动（见 2.6）。

### 2.2 Vidu（数字人引擎）⚠️ 未验证（无真实凭据）

| 项 | 值 |
|---|---|
| 凭据 | 环境变量 `DH_VIDU_KEY`（必需，real 模式） |
| 模式 | `engine.mode`：`real`（默认）/ `dev`（假引擎，仅本机联调）；也可用 `DH_ENGINE_MODE` 覆盖 |
| 覆盖地址 | `engine.vidu_base_url` / `engine.vidu_ws_url`（环境变量 `DH_VIDU_BASE_URL` / `DH_VIDU_WS_URL`），仅联调验收用，默认 `https://api.vidu.cn` 及其 wss |
| 云录制 | `engine.recording_enabled` 或 `DH_RECORDING_ENABLED=1` |
| 缺失时表现 | `StartLive` 返回 503 `engine_unavailable`（✅ 已实测，见 1.5）；`/healthz` 的 `capabilities.vidu=false` |
| 如何验证已生效 | `/healthz` 的 `capabilities.vidu` 变 `true`；`engine.mode=dev` 时启动日志出现 `WARN using fake live controller` |

心跳参数（设计事实，待真机验证）：`ping_interval=10`、`ping_timeout=20`（秒）。⚠️ 未验证。

### 2.3 OmniVoice（TTS 边车）⚠️ 未验证（本机未安装）

| 项 | 值 |
|---|---|
| 凭据 | 环境变量 `DH_OMNIVOICE_ADDR`（必需，real 模式），如 `http://127.0.0.1:9880` |
| 缺失时表现 | 与 Vidu 一样导致开播 503；`/healthz` 的 `capabilities.omnivoice=false`；声音面板的试听/合成不可用 |
| 如何验证 | `capabilities.omnivoice=true`；声音面板「试听」能出声 |

### 2.4 RTC 画面凭据

配置块 `rtc:`（yaml）+ 环境变量：

| 字段 | 默认 | 说明 |
|---|---|---|
| `rtc.mode` / `DH_RTC_MODE` | `disabled` | `disabled`：明确不配置，接口返回 `mode=unconfigured, ok=false`（HTTP 200，**不是错误**）；`dev`：本地 HMAC 签发；`managed`：厂商签发器（未装配时仍 fail-closed 为 unconfigured） |
| `rtc.provider` / `DH_RTC_PROVIDER` | `artc` | 只允许 `artc` / `trtc`，其他值启动报错 |
| `rtc.room_prefix` / `DH_RTC_ROOM_PREFIX` | `dh-` | 房间号前缀 |
| `rtc.token_ttl` | `10m` | 凭据有效期；前端按 `expires_at` 提前自动刷新，刷新失败保留旧凭据并提示降级 |
| `DH_RTC_API_KEY` / `DH_RTC_API_SECRET` | 无 | dev 模式 HMAC 签发用密钥，只走环境变量 |

接口：`GET /api/v1/live/rtc-token?session_id=...` 返回 `{mode, provider, token, expires_at, room_id, user_id, ok}`（`expires_at` 为 epoch 毫秒）。

### 2.5 LLM 端点 ✅ 链路已接通（缺真机 key 联调）

LLM 组设置（`base_url` / `model` / `temperature` / `max_tokens` / `system`）落库后下次连线生效；对话链路已接通：`dm_anchor` 弹幕主播模式经 chat.Manager 调 LLM（wire 装配见 `cmd/dh/wire.go`），管理面另有 `POST /api/v1/chat` 对话接口（需开播会话；未开播 409 `not_live`、LLM 未配置 503 `llm_not_configured`、上游失败 502）。`api_key` 已实现密钥托管：PG 落库为 `enc:v1:` 自识别密文，Windows 使用 DPAPI，非 Windows 使用 AES-256-GCM 并要求 `DH_SECRET_KEY`；启动时对存量明文执行幂等迁移。GET 清空 `api_key`，仅通过 `api_key_tail8` 回显尾 8 位。剩余缺口：未用真机 key 做联调验证。

### 2.6 PostgreSQL / Redis

配置块 `data:`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `data.postgres_dsn` | 空 | 空 = 降级运行（内存存储，重启即丢） |
| `data.redis_addr` / `data.redis_password` | 空 | 空 = ticket/nonce/幂等用进程内实现 |
| `data.connect_timeout` | `5s` | 连接超时 |
| `data.required` | `false` | `true` 时连不上 PG/Redis 直接拒绝启动 |
| `data.event_retention_days` | `90` | 事件保留天数（PG 侧清理口径） |

**内存降级差异（重要）**：ticket / nonce / 幂等结果重启即丢、多实例不共享；弹幕内存降级只留最近 512 条，不提供复盘查询。契约测试由 `DH_TEST_PG_DSN` / `DH_TEST_REDIS_ADDR` 环境变量门控，未配置时自动 Skip。⚠️ PG/Redis 真机未验证。

### 2.7 其他配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `server.http_addr` | `127.0.0.1:8795` | 监听地址；`local` 模式必须是回环地址否则拒绝启动 |
| `server.read_timeout` / `write_timeout` / `shutdown_timeout` | `15s` / `30s` / `5s` | 全局短超时只作用非 WS 路由；`/ws/v1/events` 长连不受其限制 |
| `server.metrics_loopback` | `true` | `/metrics` 仅允许回环访问 |
| `log.level` / `log.format` | `info` / `json` | 日志输出到 **stdout**（无日志文件，见 §5） |
| `billing.credits_poll_s` | `60` | Vidu 积分轮询秒数，蓝本口径 `max(30, credits_poll_s)` ⚠️ 未验证 |

### 2.8 配置校验（启动即失败的组合）

- `security.mode=local` 但监听地址不是回环 → 报错「改用 lan 模式」。
- `security.mode=lan` 但 `admin_token_sha256` 不是 64 位十六进制 → 拒绝启动。
- `security.mode=collector` 但未设 `collector_secret`/`DH_COLLECTOR_SECRET` → 拒绝启动。
- `engine.mode` / `rtc.mode` / `rtc.provider` 出现非法取值 → 拒绝启动。

## 3. 13 组设置逐项说明

读本节你能：知道每个字段填什么、保存后何时生效、填错的后果。

**通用机制**（✅ 已实测）：

- 入口：直播台右上角「快捷设置」（抽屉）或「全部设置」（`/settings` 页），两者共用同一份数据。
- 保存以**全部 13 组整体提交**；接口带 `revision` 乐观锁，别人先改了会返回 `409 settings_revision_conflict`（实测报文：`settings_revision_conflict: base=999 current=1`），此时刷新（点「重载」）后再改。
- 只提交部分分组会被拒绝：`409 settings_validation_failed: 必须提交全部 13 组设置`（✅ 已实测）。
- 抽屉页脚会显示「需重载：xxx」提示哪些组要下次连线生效；「重载」按钮调用 `POST /api/v1/settings/reload`，目前只把 `danmaku.mode` 真实应用到运行时。
- 生效时机以后端设置矩阵为准，共 13 组：**即时 5 组**——声音（voice）、专属会员（member）、礼物合并播报（gift）、画面内字幕层（captions）、弹幕主播模式（danmaku）；**下次连线 8 组**——会话（session）、人设（persona）、LLM（llm）、自备 RTC（rtc）、动作库（action_library）、资产库（assets）、Vidu Key（vidu_key）、其他（misc）。每组标题旁的徽标会标明「即时 / 下次连线」。
- 无 PG 时设置保存在进程内存，**重启恢复默认**。

## 4. 安全模式：local / lan / collector

读本节你能：按部署场景选模式、配 token、排查 401/403。

| 模式 | 适用场景 | 鉴权方式 |
|---|---|---|
| `local`（默认） | 只在本机用 | 仅允许回环 IP 访问，无需 token |
| `lan` | 局域网/反向代理后多人访问 | 除 WS 外所有接口需 `Authorization: Bearer <token>` |
| `collector` | 有弹幕采集器上报 | `/api/danmaku`、`/api/v1/danmaku` 走 HMAC 签名，其余接口走 Bearer |

### 4.1 local

- 只监听回环地址（`127.0.0.1` / `localhost` / `::1`），配了非回环地址直接拒绝启动。
- 非本机来源的写请求返回 `403 {"error":"loopback_only"}`。
- Origin 只允许 `http://127.0.0.1[:port]`、`http://localhost[:port]`、`http://[::1][:port]`。

### 4.2 lan

1. 生成 token 的 SHA256（64 位小写十六进制），PowerShell：

```powershell
$tok = '换成你自己的强随机串'
(Get-FileHash -Algorithm SHA256 -InputStream ([IO.MemoryStream]::new([Text.Encoding]::UTF8.GetBytes($tok)))).Hash.ToLower()
```

2. 写进 yaml `security.admin_token_sha256`（或环境变量 `DH_ADMIN_TOKEN_SHA256`），`security.mode: "lan"`。
3. 需要跨域时把前端来源加进 `security.allowed_origins`（精确匹配，忽略大小写与末尾斜杠），否则 `403 origin_not_allowed`。
4. 前端使用：直播台顶部输入 Bearer token →「应用」。token 只存内存，刷新页面需重新输入；失效时顶部出现「凭证失效」横幅。

✅ 本机实测（lan 模式实例）：无 token → `401 {"error":"unauthorized"}`；token 错误 → 401；token 正确 → 200。

### 4.3 collector

- 采集器对 `POST /api/danmaku`（或 `/api/v1/danmaku`）计算签名：
  - 头：`X-Dh-Ts`（秒级时间戳）、`X-Dh-Nonce`（随机串）、`X-Dh-Sign`
  - `X-Dh-Sign = HMAC_SHA256(secret, method + "\n" + path + "\n" + sha256_hex(body) + "\n" + ts + "\n" + nonce)`
- 时间窗 300 秒，超时或改 body 后原签名 → `401 collector_signature_invalid`；nonce 一次性（内存实现，重启清空；Redis 版可多实例共享）。
- 密钥：`security.collector_secret` 或环境变量 `DH_COLLECTOR_SECRET`。
- Ingest 接口永远返回 200 + `{ok, reason}`（采集器依赖此语义，不会返回 4xx 业务错误）。

### 4.4 WebSocket ticket（三种模式通用）

1. `POST /api/v1/ws-ticket?session_id=<场次ID>` → `{ticket, expires_at, ttl_s}`（`security.ticket_ttl` 默认 60s）。
2. 连接 `GET /ws/v1/events?session_id=<场次ID>`，通过子协议头传票：`Sec-WebSocket-Protocol: dh.v1, ticket.<ticket>`（**不放 URL query**）。
3. ticket 一次性、与场次绑定：跨场次复用 / 过期 / 重复使用 → 401 `ticket_invalid_or_used`；握手失败不烧票（可重试）。
4. 断线补齐：重连时带 `after_seq`，服务端补发 `seq > after_seq` 的事件；去重靠 `event_id`。

### 4.5 公开与受限路由速查

| 路由 | 鉴权 |
|---|---|
| `/healthz`、`/api/health` | 公开 |
| `/metrics` | 仅回环（否则 `403 metrics_local_only`） |
| `/ws/v1/events` | 由 handler 消费 ticket（过滤器放行） |
| 其余全部（含所有写接口） | local=回环；lan/collector=Bearer |
