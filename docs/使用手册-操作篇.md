## 1. 页面与入口

| 页面 | 路由 | 内容 |
|---|---|---|
| 直播台 | `/` | 舞台区、右栏（字幕/事件）、7 个浮窗面板、底部输入条与统计条 |
| 全部设置 | `/settings` | 13 组设置（内嵌抽屉组件）+ 界面偏好（主题、密度、右栏宽度等，仅本机生效） |
| 平台 | `/platform` | 抖音推流目标配置、推流状态与启停、采集（弹幕）房间配置与状态（见 §8） |
| 形象档案 | `/avatars`、`/avatars/new`、`/avatars/:id/edit` | 形象档案列表、新建与编辑（CRUD、素材、激活、refs 绑定，见 §6） |

直播台右上角：Bearer token 输入框（lan/collector 模式用，只存内存）、「全部设置」、「快捷设置」（弹出同一个设置抽屉）。

✅ 本机实测：生产构建（`web/dist/spa`）静态托管后页面完整渲染——头部、7 个面板按钮（声音/动作/弹幕/口播/参考图/歌曲/复盘）、舞台区（未开播 / WS 离线 / 喂流未持有）、底部「开始直播（F9）」均正常显示；后端不可达时显示错误提示而非白屏。

## 2. 舞台区（VideoStage）

- 顶部状态：场次阶段、liveId、时长、WS 状态（在线/轮询/离线）、音频延迟、喂流权（持有/未持有）。
- 视频区：RTC 播放器。凭据未配置时显示「RTC 未配置（后端未下发凭据）」——**这是正常状态不是错误**；凭据存在时自动入会，并在 `expires_at` 到期前自动刷新，刷新失败保留旧画面并提示降级。
- 字幕层：叠加在画面上，受「画面内字幕层」设置组控制（即时生效）。
- 底部按钮：开始直播（F9）/ 停止直播（F10）。`F10` 与停止按钮只打开「下播确认」，显式激活「确认下播」后才停止；`Esc` / 取消保持直播中。引擎不可用时开播失败并显示错误原因。

## 3. 七个面板

面板从面板栏点击开启，浮窗可拖拽、折叠、关闭；布局偏好自动保存在本机。

### 3.1 声音（VoicePanel）

- 音色预设：输入 voice preset id →「应用」（写入 voice 组设置，即时生效）。
- 音色音频库：上传音频文件、按绝对路径导入文件夹（白名单限制在 `storage/` 之下）、删除文件、刷新列表。
- 接口：`/api/v1/tts/voices`、`/tts/voice`、`/tts/upload`、`/tts/import-folder`、`/tts/delete`、`/tts/queue` 等 8 条。
- ⚠️ 未验证：OmniVoice 边车未接入时，音色列表为空、试听无声。

### 3.2 动作 / 指令（CommandPanel）

- 动作库管理：新建库（「建库」）、库下加动作（「加动作」）、右键动作删除、删除库。
- 手动触发：发送动作指令；可停止当前动作（`POST /api/v1/live/actions/stop`）、清空队列（`/actions/clear`）。
- 编排（choreo）：配置分组与步骤、启动/停止/「执行一轮」；调度按优先级 `vip=3 > manual=2 > choreo=1 > 其他=0`；VIP 弹幕动作直发不排队并暂停编排 4.5s。冷却：自动不同动作 2s / 自动同动作 8s / 唱歌 6s / 手动 0s（手动同动作 2s）；队列上限 3（超出时丢弃队尾最低优先级并计数）。
- 接口：`/api/v1/actions/*`（8 条）+ `/api/v1/choreo/*`（8 条）。⚠️ 动作到画面的实际驱动未验证（无真实引擎）。

### 3.3 弹幕（DanmakuPanel）

- 显示当前模式与热词 Top（统计口径：自然日 `calendar_day`）。
- 「应用模式」切换 off/confirm/auto（即时生效）。
- confirm 模式下对待播报队列逐条「确认 / 忽略」。
- 接口：`/api/v1/danmaku/state`、`/pending`、`/mode`、`/confirm`、`/dismiss` 5 条；弹幕上报走 `POST /api/danmaku`（采集器 HMAC，见配置篇 §4.3）。

### 3.4 口播（KouboPanel）

- 文本框输入口播稿 →「拆分」（按标点分段，默认每段 ≤120 字）。
- 每段：「合成」（TTS）、「试听」、「动作」、按光标位置「拆分该段」；勾选多段可「合并」。
- 批量：「合成全部」「全部动作」「整篇播放」「停止」。
- 工程持久化在 `storage/koubo/project.json`，重启后恢复。⚠️ 合成/播放依赖 OmniVoice 与播放器，未接入时合成会失败并显示错误。

### 3.5 参考图（RefsPanel）

- 添加参考图（资产 ID 可选 + 图片 URL）、「下发切换」（推送给当前场次）、「移除全部」。
- 切换失败（Vidu type14）只回显降级，不影响开播状态。
- 接口：`GET/POST /api/v1/prompt`、`POST /api/v1/prompt/type14`。⚠️ 实际推送需真实 Vidu 会话，未验证。

### 3.6 歌曲（SongsPanel）

- 「上传歌曲」、列表「点播 / 删除」、可选逐行歌词、「停止」。
- 歌曲文件落在 `storage/songs/`；切歌/停止会推进事件 `epoch`（歌词字幕优先于口播字幕）。
- 接口：`/api/v1/songs/*` 6 条。⚠️ 实际出声依赖 ffmpeg 解码与喂流，未验证。

### 3.7 复盘 · 成本（ArchivePanel）

- 场次列表（分页、按阶段筛选）：阶段、时长、录制状态、错误码、成本摘要。
- 点进单场看详情 + 事件流；「导出 JSON」「导出 CSV」触发浏览器下载。
- 接口：`/api/v1/sessions`、`/api/v1/sessions/{id}`、`/sessions/{id}/export`、`/api/v1/cost/*`。
- 无 PG 时：内存降级只保留当前进程数据，重启后列表清空（弹幕内存降级只留最近 512 条，不提供复盘查询）。

## 4. 右栏与底部

- **右栏**：字幕流（transcript.partial/final 实时事件）与事件流两个页签（事件页签由字幕设置组 `show_events` 控制显隐）；「清空字幕」有二次确认，清空不可恢复。
- **输入条（ComposerBar）**：输入框 Enter 发送、Shift+Enter 换行；以 `/` 开头的文本作为控制台指令发送；模式可切「按句 / 整段」（对应 say 的 sentence/whole）；按钮：发送 / 打断 / 停止。仅在开播状态下可说话。
- **统计条**：积分、Token、钻石、礼物、时长、音频延迟。钻石/礼物在统计未接入时显示「—」并标注来源。

## 5. 事件流与断线补齐（用户可感知的行为）

- 事件信封：`seq, event_id, session_id, type, ts_ms, epoch, request_id, payload`。`seq` 按场次单调递增；`epoch` 是喂流/歌曲代际，切歌或重连时 +1。
- WS 断开时前端自动转为 15 秒 REST 轮询兜底，恢复后带 `after_seq` 补齐缺失事件，不会漏也不会重。
- 只有**切换场次**才会清空事件列表与去重表；切歌、切参考图、触发动作不会清空。

## 7. 开播 / 下播流程

### 7.1 开播前置检查清单

1. `GET /healthz`：`capabilities.vidu=true`、`capabilities.omnivoice=true`（假引擎联调时 `engine_dev=true` 也可以）。
2. 需要画面：`rtc.mode ≠ disabled` 且能拿到 `ok=true` 的凭据。
3. 设置组「会话」：`avatar_id` 或 `image_uri` 至少填一项；「人设」：`active_id` 按需。
4. lan/collector 模式：顶部已填有效 Bearer token。

### 7.2 开播

- 界面：点「开始直播（F9）」。前端实际发送 `POST /api/v1/live/start`，字段 `personaId / avatarId / greeting / idempotencyKey`（`Idempotency-Key` 请求头与 body 内幂等键必须一致，不一致返回 `400 idempotency_key_mismatch`）。
- 重复开播：**不会报 409**，服务端先对当前场次执行 `stop(reason=reconnect)` 再重新开播。
- 成功返回 `{session_id, phase, live_id}`，舞台区状态转为直播中。
- ⚠️ 真实开播（Vidu 建场 → 信令 → 首帧 → 48B/ms 喂流）未验证，需 Vidu Key 到位后按联调清单验收。

### 7.3 下播与异常停止

- 正常：按 `F10` 或点「停止直播」打开「下播确认」，显式激活「确认下播」后才调用 `POST /api/v1/live/stop`（reason=`manual`）；`Esc` / 取消不调用 stop，保持 `live`。
- 达到 `idle_timeout_s` 闲置或 `max_duration_s` 上限：引擎侧自动收（⚠️ 未验证）。
- 进程崩溃重启后：遗留的 `starting/live/stopping` 状态场次会被标记为 `error(crash_recovered)` 并发出 `live.crash_recovered` 事件——**不会自动续播**，需在复盘面板确认后手动重开。

### 7.4 怎么确认真的在播

1. 舞台区状态 = 直播中，时长在走，`feed.owner=持有喂流`。
2. `GET /api/v1/live/status`：`phase=live`，`ws.state=connected`，`eventSeq` 随事件递增（✅ 该接口形状已实测）。
3. 说一句话：右栏字幕流出现 partial → final，舞台字幕层同步显示（⚠️ 出声链路未验证）。
